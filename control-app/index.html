Full Connection Path

Everything should move through one governed path. Live customer traffic is separate from internal owner authority, approvals, and memory writes.

1
Input
Website form or manual n8n test creates the intake payload. Future inputs such as voice, SMS, browser, and email should be converted into the same event envelope.
2
Normalize
n8n converts messy customer answers into a stable JSON object with request ID, contact details, service interest, urgency, budget, risk flags, and raw intake.
3
Review
AI produces Dominique's internal report and a customer-safe draft. It must never tell the customer that a plan was sent or expose internal automation logic.
4
Record
Google Sheets receives the tracker row. Postgres should receive governed event, task, decision, policy, memory, and verification records once wired.
5
Gate
Any external send, quote, credential change, production change, spending, or destructive action must pass the deterministic policy gate and owner approval path.
6
Act, Verify, Remember
Only approved actions execute. The result is checked, logged, and written to memory only when verification succeeds.

Failsafes And Security Measures

The system should fail closed. If it cannot prove the action is safe, authorized, scoped, and reversible where needed, it stops and asks Dominique.

GateRequired CheckFailure Behavior
Root authorityDominique Reed is final authority for restricted actions.Stop and request owner approval.
Credential scopeNo secret values in browser, emails, Sheets, Drive docs, prompts, or customer replies.Deny and log as credential exposure risk.
Destination allowlistEmail addresses, Sheet IDs, Drive folder IDs, APIs, and domains must be explicitly approved.Block until allowlist entry exists.
Policy classCustomer reply, quote, payment, production deploy, access sharing, deletion, and credential changes need approval.Create approval request, do not execute.
RollbackDestructive or production actions need rollback method and verification method.Deny if rollback is missing.
VerificationExecuted action must return proof such as message ID, row range, file ID, or deployment ID.Do not write success memory.
Memory writeOnly verified, scoped, non-secret information can become memory.Store as candidate or reject.
